# 主管与外部子智能体协作规则

此文件是可合并到 `~/.codex/AGENTS.md` 的规则模板，不会自动安装或覆盖用户现有规则。全局默认适用于本机各项目；项目规则与用户本次授权仍需遵守，不会自动同步到其它电脑。

- 适合委派的独立子任务尽量交给可用的 ZCode 或 GLM 执行器。日常优先考虑已验证的 OpenCode GLM；需要 Codex CLI 环境时用直连 GLM；需要 ZCode 会话与 profiles 时用 MCP 中继。简单任务由主管直接完成，不为委派而拆分。
- 原生 Codex 子智能体在外部执行器不可用、不适合任务或用户明确要求时作为补充。不创建或恢复旧员工聊天，不自行启用后台定时协作。
- 阅读、实现与初步审查可交给 GLM，主管保留必要验收。清晰轻量任务优先 Flash/low；复杂任务按需要选择完整 GLM 与已验证强度。用户明确指定模型与强度时严格遵守，不静默降级，不把模型自述当作配置证据。
- 每次派发使用任务文件，明确目标、工作目录、文件所有权、允许的工具与外部操作、产物和验收标准。只传必要上下文；Key 复用本机已保存认证，不进入任务、代码、Git 或回报。
- 派发后主管保持当前回合。先处理其它独立工作；无可推进工作时等待原生消息、MCP 完成事件或实际执行进程退出。不得状态轮询、定时催问、空转推理或创建轮询自动化。
- 单段等待超时仅结束该段等待，不意味着任务完成。遵守单次工具等待限制，继续等待同一任务的真实回报；不设置短的任务总等待时限。运行时遇到不可自行解决的阻塞，应如实说明，而非无限重试。
- 不假定已结束的主管回合必然被外部消息唤醒。接口无法保证恢复时保持当前回合的事件／进程等待。
- 子智能体的完成回报、退出 0 或 `executionCompleted:true` 只是待验收。主管独立检查改动、授权范围和适当测试；失败派发明确返修任务，成功后收尾或进入下一项。
- 对已有且适用的空闲执行器，用能启动新任务的派发操作；普通消息可能只投递内容。并发仅用于独立任务，各自拥有明确文件范围和结果目录，必要时使用独立 worktree。
- 子任务完成后关闭它独占的临时进程或客户端；保留其它任务使用的共享 ZCode 路由器、broker 或 OpenCode 服务。MCP 状态和模型执行是否停止须分别确认。
- 委派不扩大用户授权。系统权限、工具权限和用户授权不同，不宣称自动继承主管所有审批、连接器和沙箱。不宣称协调零 token 成本或已量化净省 token。
- 主管只在验收与收尾完成、用户明确暂停、确需用户决定，或不可自行解决的运行时阻塞时结束回合，不只报告“已派发”后留下验收。

执行命令、权限和模板见各路径 README、[权限说明](permissions-and-lifecycle.md)与[任务卡](../templates/task-card.md)。
